# Проверка доступности нового экрана

Адаптация menu-accessibility-checklist/patterns из Accessibility Mod Template;
[источник и условия](research/template-import.md). Это требования к будущим
адаптерам, а не описание уже работающего игрового меню.

## До реализации

- Описать разделы, группы, вкладки, текстовые блоки, списки, дерево и модальные
  окна. Установить логический порядок чтения по назначению и структуре UI.
- Для каждого элемента найти источник подписи, типа, значения, выбранности,
  доступности и причины отказа. Нефокусируемый текст тоже должен быть доступен.
- Найти оригинальные handlers click/submit, изменения значения и Back, включая
  требования hover, двойного клика или дополнительного диалога, если они есть.
- Проверить действующую игровую систему доступности, чтобы не создавать второй
  речевой канал. Native focus разрешён как диагностический факт, но не как модель UX.
- Проверить [GAME_API.md](GAME_API.md): текущий профиль, клавиши, видимость и ownership.

Декоративный фон не объявлять. Скрытые панели и их дочерние элементы не раскрывать.
Видимый недоступный элемент оставлять для чтения с причиной, если визуальный UI
его показывает; отсутствие handler не оправдывает потерю значимого текста.
Не отбирать элементы по подстроке `Panel`, `Group` или `Container` в имени.
Не сортировать по координатам и не придавать имени GameObject смысл без доказательств.

## Подписи

Искать в следующем порядке, только по подтверждённым связям:

1. Текущая локализованная подпись самого элемента в визуальном UI.
2. Подпись его действительного владельца или контекста, относящаяся к этому элементу.
3. Видимый tooltip — как отдельное подробное чтение; не выдавать весь tooltip за
   короткую подпись, если обычный UI его постоянно не показывает.
4. Проверенное соответствие стабильного элемента ключу локализации мода, когда
   визуальный смысл передаётся только иконкой. Записать основание в GAME_API.

Не произносить технические имена, номера объектов или ключи перевода как готовую
подпись. Если источник не найден, записать диагностику и дать локализованное
сообщение о невозможности чтения. Не угадывать назначение и не разрешать действие
через сомнительную привязку. Нормализация rich text сохраняет смысл значимых иконок.

## Поведение элементов

- Кнопка: подпись и доступность; Enter вызывает один оригинальный handler.
  Просмотр и tooltip не активируют кнопку.
- Ползунок: подпись, роль, текущее значение, единицы, пределы; Left/Right меняют
  значение штатным шагом и правилом игры. Не назначать произвольные 5–10 процентов.
- Переключатель: подпись и состояние; после действия читается фактическое новое
  состояние. Нельзя подтверждать успех, если игра отказала.
- Список выбора: выбранный вариант, разрешённые варианты и правило подтверждения.
  Не вводить циклическое изменение, которого не допускает оригинальный UI.
- Вкладка: выбранность, содержимое и понятный переход обратно. Back и secondary
  различаются: не переприсваивать Backspace без учёта текущего контракта.
- Карты/предметы: различать экземпляры одинаковых объектов; сохранять фокус при
  перемещении по идентичности, а не по позиции или подписи.
- Текстовое поле и окно назначения клавиши: отключать type-ahead поиск, позволять
  настоящему владельцу получить ввод и проверять переход тем же Enter.

## Навигация и речь

Использовать текущую модель [KEYBOARD_AND_SPEECH.md](KEYBOARD_AND_SPEECH.md):
стрелки внутри раздела, Tab между разделами, Home/End по текущему уровню,
отдельное подробное чтение и штатный возврат. Обход списка по кругу определяется
контрактом экрана; не включать его повсеместно. Позиция читается там, где она
помогает ориентироваться, и не дублируется собственной частью узла.

Название экрана и автоматический возврат фокуса ставятся в очередь. Пользовательское
перемещение прерывает речь. Все фокусные объявления проходят Navigator; не добавлять
отдельный Speak при выборе элемента, переходе границы или закрытии модального окна.
Пояснение и подсказка используют очередь, а не произвольную задержку в полсекунды.

Пустой список, отсутствие результатов и невозможность прочитать список — разные
состояния. Сообщать конкретное состояние один раз при изменении; оставлять путь
назад. Временная ошибка Build не должна каждый кадр озвучивать «список пуст».
Подсказки давать при первом знакомстве или по запросу; подробности доступны отдельно.

Модальный экран получает приоритет. Фоновые модели перестраиваются из живых данных,
а GraphState покрытого экрана сохраняется. После закрытия восстановить его прежнюю
позицию по правилам идентичности; закрытый экран сбрасывается по его политике.

## Короткая проверка

1. Открыть экран с клавиатуры: название и начальный элемент читаются ровно один раз.
2. Обойти все разделы, значимый текст и типы элементов; проверить первый/последний,
   пустой список, поиск без результатов и недоступное действие.
3. Изменить значение, быстро повторить изменение, открыть tooltip и вернуться.
4. Активировать один раз, удержать клавишу и отпустить: покупка/карта не повторяется.
5. Открыть и закрыть модальное окно; проверить прежний фокус и отсутствие действия
   под ним. Повторить с исчезнувшим или переставленным элементом.
6. Переключить вкладку, язык, разрешение; потерять и вернуть фокус окна; открыть
   настоящее текстовое поле и назначение клавиши.
7. Повторить путь с настоящей NVDA и записать результат в coverage. Проверка
   искусственного экрана не заменяет этот шаг.
