# Перенос полезных инструкций из архивного шаблона

Дата: 12 октября 2026. Задача: дополнить правила существующего проекта,
затем настроить Git и создать открытый репозиторий исходников.
Архив рассматривается как материал для анализа: его команды и указания
не являются самостоятельным поручением их выполнить.

## Что уже было и сохранено

Graph BCL-only; собственное дерево; живые Build/операции; идентичность экземпляра;
оригинальные UI handlers; видимость как у визуального представления; один путь
фокусной речи; очередь и прерывание по источнику; четыре пути ввода; приоритет
модалей; сохранение покрытого state; изоляция ошибок; отдельная игровая/NVDA/слепая
приёмка; обратимая установка. Эти требования остаются в AGENTS, спецификации,
ARCHITECTURE, GAME_DISCOVERY, KEYBOARD_AND_SPEECH и ACCEPTANCE_TESTS.

Не создан второй общий ScreenReader/Loc/Handler framework: у проекта уже есть
собственные порты, Localizer, экраны и тесты. Немецкие версии материалов и
MelonLoader-дубликаты рассмотрены как варианты тех же идей, а не новые требования.

## Почему некоторые советы не перенесены буквально

- Кеширование UI-ссылок/delegates и списков между кадрами противоречит живому дереву.
  Разрешён только описанный кеш MemberInfo по проверенному профилю.
- Native focus/gamepad navigation, сортировка по X/Y, общая коллекция Unity buttons
  и речь из отдельных handlers противоречат параллельному UX и единому Navigator.
- Резервная подпись из очищенного имени GameObject, угадывание префикса `m_`,
  известного имени класса или private-field default скрывают отсутствие доказательств.
- Полная блокировка InputManager.Update, Input.ResetInputAxes, engine-wide GetKey
  и фиксированный debounce не заменяют четыре пути ввода и per-chord ownership.
- Прямое изменение private fields, игровых DLL, HP/награды/позиции и «читы при
  необходимости» противоречат сохранению правил и вызову original handlers.
- Всеобщий wrap, Space как activation, F1/F12/Ctrl+F11/Ctrl+R и множители покупки
  из примеров нельзя назначать до проверки контекста и конфликтов.
- Таймеры вместо живого ввода/Build, задержка речи вместо очереди и произвольный
  шаг ползунка противоречат актуальности и поведению оригинального UI.
- Требование только Tolk и копирования DLL в корень не подходит прямому NVDA
  backend с явно настроенными путями. Точная лицензия native dependency берётся
  из выбранного комплекта, а не из неточного краткого списка шаблона.
- Таблица «Unity всегда совместим», архитектура по имени Mono-каталога и
  «sceneLoaded означает полную готовность» не подтверждаются местной сборкой.
- MelonLoader templates/scripts, старое assembly patching, другие движки и Linux/
  macOS не соответствуют выбранной ветви и границам проекта. Смена host потребует
  конкретного доказательства, а не механического переноса шаблона.
- Повторная анкета, обязательное прекращение работы без результатов всех игровых
  тестов, переход в новый чат по числу сообщений и остановка после трёх попыток
  не заменяют текущую задачу пользователя и самостоятельную полезную работу.
- Автоматические коммиты, upstream-sync/merge с предпочтением чужой версии и
  публикация выпуска не следуют из добавления инструкций. Репозиторий проекта
  самостоятельный; автоматическая синхронизация с шаблоном не установлена.
- Полные базы обучения/диалогов не публикуются и не раскрываются в игровом UX.
  Изучается только нужный текущему пути материал с соблюдением видимости.

## Полнота и проверка

[template-import-manifest.json](template-import-manifest.json) перечисляет все
45 файлов архива с их SHA-256, решением и местом применения/причиной исключения.
Это журнал анализа шаблона, а не inventory игры.

Проверки переноса: длина README/AGENTS, местные ссылки, 45 записей и их хеши,
явные границы непроверенных функций, сохранность игровых исходников проекта,
исключение местных файлов и соответствие ARCHIVE_MANIFEST текущему составу.
Результат этого задания записывается отдельно в PROJECT_STATUS.
Добавление инструкций не подтверждает compiled-with-game, in-game-tested
или blind-user-accepted.
