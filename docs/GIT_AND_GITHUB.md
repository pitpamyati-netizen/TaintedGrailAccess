# Git и GitHub в этом проекте

Адаптация git-github-guide из Accessibility Mod Template;
[источник и условия](research/template-import.md).

Git хранит историю сохранённых состояний проекта — коммитов. GitHub хранит
удалённую копию исходников и принимает сообщения об ошибках. Репозиторий
с исходниками не является готовым модом или пользовательским выпуском.

## Когда выполнять действия

Агент использует Git только по конкретному текущему поручению пользователя.
Это касается также `status`, `diff`, веток и подготовки коммита. Первоначальная
настройка и публикация не дают разрешения автоматически отправлять каждую
следующую правку. Команды ниже — справка для явно порученной работы.

В проекте используется основная ветка `main`, удалённая копия называется `origin`.
Настройки имени автора и скрытого GitHub email задаются для этого репозитория,
чтобы не менять другие проекты. Пароли и токены не записываются в документы,
remote URL или коммиты; используется уже авторизованный GitHub CLI.

## Перед коммитом

Из корня проекта:

```powershell
git status --short
git diff --check
git diff -- README.md AGENTS.md docs
```

Проверить смысл и состав изменений. Добавлять нужные файлы явными путями:

```powershell
git add -- README.md AGENTS.md docs/DEVELOPMENT_GUIDE.md
git diff --cached --check
git diff --cached --stat
git diff --cached
git commit -m "Уточнить правила разработки и проверки экранов"
```

Сообщение коммита объясняет конкретный результат. Не добавлять игровые файлы,
декомпиляцию, логи, сохранения, архивы, ключи или личные конфиги. `.gitignore`
защищает новые файлы, но не удаляет ранее сохранённое из истории.
До публикации проверять именно подготовленные файлы и их содержимое.

## Отправка и проверка

```powershell
git push -u origin main
git rev-parse HEAD
git ls-remote --heads origin main
gh repo view --json nameWithOwner,url,visibility,defaultBranchRef
```

Локальный и удалённый идентификатор последнего коммита должны совпадать.
Проверить адрес, владельца и доступность репозитория. Следующая явно порученная
отправка может использовать `git push`, если ветка уже связана с origin/main.

## Если возникает проблема

- Git просит автора: проверить локальные `user.name`/`user.email`; не угадывать
  личную почту. Для GitHub можно использовать его адрес noreply.
- Ошибка входа: проверить `gh auth status`; авторизация проходит штатно, без
  пересылки токена в чат. Не сохранять секрет в URL.
- Удалённая ветка изменилась: получить состояние и изучить различия, сохранить
  местную работу, объединить изменения осмысленно. Не делать force push.
- Ошибочно добавлен приватный файл: остановить публикацию и убрать его из
  подготовленного коммита. Уже опубликованный секрет требует отзыва; простое
  удаление файла новым коммитом не стирает прежнюю историю.
- Ошибка слияния: разбирать каждый конфликт и проверять результат. Не выбирать
  автоматически «всё из удалённой версии» и не запускать upstream-sync шаблона.

`reset --hard`, `clean`, восстановление файла с потерей правок, удаление ветки
и переписывание истории выполняются только при отдельном понятном поручении.
Не требовать чистого дерева ценой удаления чужой работы.

Выпуски с готовыми DLL и ZIP описаны в [RELEASE_GUIDE.md](RELEASE_GUIDE.md);
создание репозитория и `push` не запускают такой выпуск.
