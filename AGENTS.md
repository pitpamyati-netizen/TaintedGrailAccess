# Правила разработки Tainted Grail Access

## Цель и границы

Полное самостоятельное прохождение Tainted Grail: Conquest на Windows x64
со скринридером и без мыши. Это Conquest, App ID 1199030; не The Fall of Avalon.
Пользователь полностью слепой, использует NVDA. Сообщения на русском,
без эмодзи; обычный отчёт не длиннее пяти строк, подробности отдельным файлом.

## Сначала прочитать

README.md, ROADMAP.md, docs/SPEC_CONFORMANCE.md,
docs/spec/graph-a11y-spec.original.md, docs/GAME_DISCOVERY.md.
Короткие README и AGENTS сохранять в пределах 5000 знаков каждый.
Перед новой работой прочитать docs/PROJECT_STATUS.md и docs/DEVELOPMENT_GUIDE.md;
перед игровым адаптером — docs/GAME_API.md и docs/MENU_ACCESSIBILITY.md.

## Общение и рабочие записи

Писать по-русски простым языком, без таблиц в ответах. Короткий промежуточный
отчёт: сделано, текущая работа, остаток, проблемы. Работать самостоятельно;
субагенты — только по прямой просьбе или для оправданной независимой работы.
Новые доказательства сразу записывать в GAME_API, важный результат и следующий
шаг — в PROJECT_STATUS. Git выполнять только по текущему поручению пользователя.
Для сборки/установки использовать scripts/build.ps1 и scripts/deploy.ps1.
Дополнения из шаблона и их границы: docs/research/template-import.md.

## Работать по доказательствам

- Не выдумывать типы, поля, Harmony targets, имена action в Rewired и API игры.
  Наличие DLL не подтверждает использование конкретного метода.
- Сначала локальный inventory и журнал загрузки. Искать в TG.Main.dll и
  Assembly-CSharp.dll; для другой установленной сборки скорректировать allowlist.
- У каждого binding: точное имя/сигнатура, SHA-256/MVID сборки, способ нахождения,
  original UI handler, проверка видимости и активности, проверенный сценарий.
- Профиль profiles/unbound.example.json намеренно неподключён. Не обходить
  недостающие доказательства заменой unknown на true. При неизвестной версии
  диагностический режим сохраняет обычное управление игры.
- Не выдавать собирающийся проект, озвученный старт или fake-screen tests за
  работающую доступность игры. Вести отдельно implemented, portable-tested,
  compiled-with-game, in-game-tested, blind-user-accepted.

## Обязательная архитектура

- Graph: только BCL; никаких Unity/BepInEx/Harmony/NVDA, ввода или Speak.
- Мод владеет параллельным деревом. Не строить UX на native focus, gamepad
  navigation, OCR или экранных координатах. Диагностический сбор текстов не UI.
- Каждый Build и операция читают живое состояние. Узлы одноразовые;
  GraphState принадлежит экрану. Не хранить старые view, delegate или render
  в игровых адаптерах между кадрами. Снимок последней речевой цепочки допустим
  только у навигатора для path diff; предыдущие delegates не вызывать.
- Reference identity объекта → structural key → предыдущий ближайший выживший.
  Индекс руки, имя карты и card-definition id не заменяют id экземпляра карты.
- Все фокусные объявления проходят один chokepoint. Пользовательский переход
  прерывает речь; фоновые события и восстановление фокуса ставятся в очередь.
  StateText после синхронного изменения перебазирует Live-watch.
- Действия вызывают оригинальный обработчик UI. Не менять HP, энергию, RNG,
  награды, инвентарь или transform.position напрямую.
- Видимость проверяется теми же правилами, что у визуального представления.
  Не раскрывать туман, будущую колоду/RNG, скрытые намерения, награды или диалоги.
- Весь собственный пользовательский текст — таблицы локализации.
  Локализованный игровой текст не переводить заново и не пересчитывать вручную.

## Ввод и жизненный цикл

- Проверить четыре пути ввода: poller, global keymap/Rewired, EventSystem/
  original action handler, эксклюзивная модальность. Подавлять только присвоенные
  сочетания текущего кадра. Глобальное отключение ввода вне mod-modal запрещено.
- Не использовать Input.ResetInputAxes как решение конфликтов. Патч engine-wide
  Input.GetKey без доказанной необходимости и узкой области не применять.
- Собственный вызов handler проходит ownership scope; физический Submit не должен
  повторить его. Исключение после действия не возвращает consumed=false.
- Нет фокуса — Enter/Space/secondary остаются игре; raw capture и текстовый ввод
  отключают поиск. Учитывать потерю окна, OS repeat и отпускание клавиш.
- Poll-and-diff экранов, приоритет модалей, состояние покрытого экрана сохранять.
  Ошибки Build изолировать и логировать один раз на экран и тип исключения.
- Освобождать только собственные hooks; unpatch по своему Harmony id.

## Завершение этапа

Минимальный воспроизводимый сценарий → нужный регрессионный тест → исправление →
focused checks → обновление ROADMAP/coverage. Не расширять проверки без причины.
Для интеграции нужны проверка в игре и проверка NVDA, включая повторный ввод.
Не публиковать игровые DLL/декомпиляцию, сохранения и логи с персональными путями.
Не заменять существующий чужой загрузчик; обновления и установка обратимы.
